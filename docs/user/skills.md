# Skills

Open **Settings > Skills** and select the environment whose files you want to manage. The list combines managed skills and discoveries from providers and configured usage locations. Duplicate physical locations are grouped; plugin-owned skills stay under their plugin's management. Paths and credentials always belong to the selected environment, including over a remote connection.

Install from a local directory, a Git repository or URL, or an enabled Meituan Skills source. When a package contains several skills, select one or more to install. Skills from the same source are grouped while keeping their own versions, policies and usage locations. Without a usage location, the skill is saved only to the library. Use **Installation sources** to configure and check installers. **Usage locations** adds directories to scan and link, including shared directories and custom agent platforms. Instances sharing a directory are configured together.

Installation selects the shared skills directory by default. Adoption also selects the original usage locations. Disabled locations are not selected automatically. You can change the selection before confirming. Shared skills are discoverable by providers that support that directory; providers such as Claude and Antigravity may require their own usage location as well. Start a new provider session after changing skills.

The list hides externally maintained skills by default. Use **Filter skills** to include them or filter by management and update status. External skills are updated through their plugin or provider.

To manage an existing skill, review its source, content and locations first. Adoption backs up the original files and replaces the selected locations with managed links, so agents use the managed skill instead of a separate unmanaged copy. If agents are active, adoption waits until the environment is idle and keeps the original files in place. Waiting requests survive server restarts and can be cancelled from recent operations. If the original content changes while waiting, preview it again before retrying. A previously copied library entry is reused when its content still matches the original. A takeover without an independent update source remains a local snapshot; connect its real upstream to enable updates. Sources are never inferred from a skill's name alone.

New managed skills default to **Automatic updates**: the environment server checks daily, prepares changes and applies them when agents are idle. The page does not need to stay open. **Manual updates** checks daily and shows an available-update indicator until you apply the candidate. **No updates** disables scheduled checks and application. Existing policies are retained until you change them. Restoring an earlier version pins it. Change the policy to resume automatic updates. Running provider sessions may need to be reloaded or replaced to use updated files.

Local edits to managed files block automatic application without changing your policy. Review the file differences, keep and pin local changes, or explicitly use the candidate version. Existing files or directories at an assigned location are automatically backed up and replaced with managed links when agents are idle. If linking fails, the original is restored when the location is still free. Backup paths appear in the skill's usage locations. Cancel a waiting update to leave the current files in place. A later check can discover new content. Batch actions run serially and show individual, persistent results in recent operations; being queued does not mean an update has been applied.

Usage locations containing skills can be disabled. This detaches their managed links and hides them from location selection while keeping the directory and original files. Disabled locations remain in the list so you can enable them again; assign skills again to restore their links. Locations without skills can be removed from the list, except the shared skills directory. Removal does not delete files. These changes apply to all instances sharing the directory.

**Stop managing, keep files** leaves ordinary files at the linked locations. **Restore original locations** restores the earliest original backup at each location and stops management. **Uninstall** removes the managed package and links and restores those original backups. Later backups, library versions and backups retained after stopping management remain in the environment's skill storage.

Web, desktop and mobile share management, update policies and results. Agents with full access can use `list_managed_skills`, `inspect_skill` and `manage_skills` on the same environment.
